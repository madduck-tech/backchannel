# 0033 — Agent instructions come from a harness-neutral source, and Claude Code gets copies

Date: 2026-10-28
Status: accepted (supersedes ADR 0032's decisions 1 and 2, and amends its decision 6)

## Context

ADR 0032 (#233, decision 2) kept `.claude/` as the one source and generated what Codex and opencode read from it. On 2026-10-28 the product owner reversed the direction (#271): the source is harness-neutral, and what Claude Code needs is generated from it.

Measured on 2026-10-28 (#271), with Claude Code 2.1.312, codex-cli 0.163.0 and opencode 2.0.32, one run per cell. Each fixture puts a unique sentinel in a file, and Claude Code ran as `claude -p --tools ""`.

**Claude Code started in `frontend/`, with Next.js's `frontend/CLAUDE.md` = `@AGENTS.md`:**

| The root holds | Root instructions reached the session |
| --- | --- |
| no `CLAUDE.md`, only `AGENTS.md` | no |
| `CLAUDE.md` = `@AGENTS.md` | no |
| `CLAUDE.md`, a full copy of `AGENTS.md` | yes |

What explains each row, and the other findings:
- **Claude Code reads a root `AGENTS.md` only as a fallback,** when no `CLAUDE.md` is on its startup chain. `frontend/CLAUDE.md` is on that chain. So ADR 0032's "Claude Code does not read a root `AGENTS.md` unless `CLAUDE.md` imports it" is no longer exact.
- **The root `CLAUDE.md` loads from a subdirectory; its `@` import does not.** That held for a relative and for an absolute import path. This was measured under `-p`. `~/.claude.json` keeps per-project `hasClaudeMdExternalIncludesApproved` keys, so an interactive session that approved the import may get it. Nobody measured that.
- **An `@` import in a `.claude/rules/` file with `paths:` loads at session start,** ignoring `paths:`. The same text written inline loads only after a matching file is read.
- **An `@` anywhere in a line imports, not only at its start.** One in a code span or a fenced block does not.
- **A full `CLAUDE.md` next to `AGENTS.md` does not load `AGENTS.md` as well.**
- **Claude Code reads neither `.agents/rules/` nor `.agents/skills/`.**
- **opencode 2.0.32 sends the root `AGENTS.md` once and `CLAUDE.md` not at all** when both exist (`opencode run --standalone` against a stub provider).
- **opencode 2.0.32 has no `debug skill` and no `run --command`.** A private `opencode serve` takes `POST /api/session/{id}/command` and sends the command's body with its argument in place.
- **Generation was manual.** No git hook existed, and only the drift test in `pnpm test` caught a forgotten run.

## Decision

1. **The sources are edited by hand; everything else is generated by `scripts/gen-agent-files.mjs`.**

   | What | Source | Generated |
   | --- | --- | --- |
   | Shared instructions and the rules every session loads | `AGENTS.md`, which holds what were `CLAUDE.md`'s section, `.claude/rules/workflow.md` and `testing.md`, plus the index of scoped rules | `CLAUDE.md`: `AGENTS.md` whole, under a "generated" header |
   | Rules scoped to paths | `.agents/rules/*.md`, each with `paths:` | `.claude/rules/*.md`, byte for byte |
   | Skills | every skill directory under `.agents/skills/` that no command generates | `.claude/skills/`, byte for byte |
   | Commands | `.agents/commands/*.md` | `.claude/commands/*.md` byte for byte; `.agents/skills/<command>/`, `.opencode/command/` and `opencode.json` as under #252 |
2. **A copy, never an import.**
   - No `@path` token (an `@` at the start of a line or after whitespace, outside code spans and fences) may appear in `AGENTS.md` or in a rule.
   - Every rule in `.agents/rules/` has `paths:`. A rule every session needs goes into `AGENTS.md`; otherwise Claude Code would load it twice.
3. **What is generated is decided by the lists, not by names.** A skill directory under `.agents/skills/` is generated when a command names it, or when `scripts/agent-files.json`, `HEAD`'s or the one on disk or staged, says it was generated from a command. Everything else there is a source. A source that carries the "Generated by" marker is an error.
4. **`AGENTS.local.md`** at the root holds a person's own instructions. It is git-ignored. `AGENTS.md` tells every agent to read it at session start when it exists. It adds to the shared instructions and never overrides them. No harness-specific file is created for it.
5. **A pre-commit hook regenerates from the index.** `.githooks/pre-commit` runs `scripts/agent-files-pre-commit.mjs`, and `prepare` in `frontend/package.json` installs it through `scripts/install-git-hooks.mjs`.
   - It refuses rather than lose work in three cases: a partial commit that would change a copy; a staged copy that is neither `HEAD`'s nor the plan's; a work-tree copy that is neither the staged one nor the plan's.
   - It is a convenience. The drift test stays the guarantee.
6. **Nothing is generated under `frontend/`.** `frontend/AGENTS.md` and `frontend/CLAUDE.md` belong to Next.js, as in ADR 0032's decision 4. With the root `CLAUDE.md` a full copy, `frontend/CLAUDE.md`'s `@AGENTS.md` is a local import, and it loads.
7. **ADR 0032's decision 6 is amended.** A backticked `.claude/…` path must resolve, or be listed as retired in `every-claude-path-resolves.test.mjs`. A retired path is admitted only in `docs/decisions/`, because an accepted ADR is not rewritten. `.claude/rules/workflow.md` and `testing.md` are retired here, and every other citation of them points at `AGENTS.md`.
8. **#271's pull request is not merged by engineering on `READY`.** This deviates from ADR 0014. The product owner decided it on 2026-10-28 for #271 only, and it is not a precedent.

## Consequences

- **Every harness reads the same text from the same file.** Codex and opencode read `AGENTS.md` itself, and Claude Code reads a copy of it. Codex's 32 KiB budget still covers `AGENTS.md` (`agents-md-fits-codex.test.mjs`).
- **Claude Code still loads scoped rules on its own,** from `.claude/rules/`. Codex and opencode still depend on following the index.
- **Editing a copy is refused by the hook and fails `pnpm test`.** People and agents used to editing `CLAUDE.md` or `.claude/` have to edit `AGENTS.md` or `.agents/` instead.
- **Some commit paths run no hook:** a clean merge, `rebase --continue`, `cherry-pick`, and `--no-verify`. Drift through those paths is caught only by CI.
- **The design rests on Claude Code's loading behaviour as measured on 2.1.312:** ancestors' `CLAUDE.md` load from a subdirectory, and `paths:` scopes a rule. A version that changes either needs these measurements redone.
