# ADR 0004: Эхо и утечка речи собеседников в канал YOU

Дата: 2026-09-01
Статус: принято

## Контекст

При раздельных потоках (ADR 0003) микрофон на динамиках ноутбука слышит собеседников: их речь распознаётся
дважды — как OTHERS и как YOU. В наушниках проблемы нет. Это деградация, не поломка.

Факты (2026-09-01):

- В Conversationaly настоящего AEC нет; есть эвристика по уровням mic/sys для угадывания говорящего на смешанном потоке.
- Форк определяет тип устройства вывода (динамики / наушники / гарнитура / Bluetooth) по имени на всех трёх ОС
  (`audio/playback_monitor.rs`).
- Project Raven: WebRTC AEC3 через GStreamer + «residual echo gate» (`src/main/residualEchoGate.ts`, ~150 строк):
  корреляция окна микрофона 100 мс с последними 400 мс системного PCM с перебором задержки, порог 0.32,
  holdover 400 мс. Работает и без AEC.
- Rust AEC: crate `webrtc-audio-processing` 2.1.0 (май 2026), живой, но требует сборки C++ библиотеки на трёх ОС.

## Решение

1. **Настоящий AEC в MVP не делаем.** `webrtc-audio-processing` — кандидат после MVP.
2. **Предупреждение о динамиках делаем в MVP.** Мастер настройки при проверке звука и экран старта встречи
   предупреждают, что на динамиках речь собеседников может попадать в YOU, и советуют наушники.
3. **Корреляционный echo gate по образцу Raven** — последний пункт Milestone 0, «если останется время»,
   иначе сразу после. Портируется на Rust без внешних зависимостей; в транскрибер прокидывается PCM
   системного канала вместо RMS.
4. **Формулировка для README и Мастера:** раздельные YOU/OTHERS гарантируются в наушниках,
   на динамиках работают с оговорками.
